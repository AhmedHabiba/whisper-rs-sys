# whisper-rs-sys (fork) — whisper.cpp 1.9.4

A fork of [`whisper-rs-sys`](https://codeberg.org/tazz4843/whisper-rs) 0.15.0 whose vendored whisper.cpp is **1.9.4** instead of 1.8.3, used by [Local Transcribe](https://github.com/AhmedHabiba/Transcribe) through `[patch.crates-io]`.

It exists because the version of whisper.cpp is not a dependency we can choose: the `-sys` crate vendors it. `whisper-rs` has published nothing since 2026-03-12, and the fix we need shipped upstream in whisper.cpp v1.9.0 (June 2026).

## Provenance

| Part | Source |
|---|---|
| Crate source | `whisper-rs-sys` 0.15.0 as published on crates.io (2026-03-12) |
| `whisper.cpp/` | [v1.9.4](https://github.com/ggml-org/whisper.cpp/releases/tag/v1.9.4) release tarball, sha256 `57e280cee375ab02425b806ad5146b99f6eb9357e3c2b31357c8a6af2e2e44ae`, with `examples/`, `tests/`, `models/`, `samples/`, `media/`, `scripts/`, `ci/` and `.github/` pruned |
| `src/bindings.rs` | Regenerated by bindgen 0.72.1 from 1.9.4's headers |

Licences are unchanged: `whisper-rs-sys` is Unlicense, whisper.cpp is MIT (`whisper.cpp/LICENSE`).

**The version stays `0.15.0` deliberately.** `[patch.crates-io]` only applies to a matching version; bump it and cargo silently ignores the patch and links the registry crate instead, with nothing but a `patch ... was not used` warning.

## What we changed, and why

Two hunks in `build.rs`. Everything else is upstream.

**1. Accept 1.9.x version declarations (required — the build fails without it).**
`get_whisper_cpp_version()` parsed `project("whisper.cpp" VERSION x.y.z)` from `CMakeLists.txt` and ended in `.expect(...)`. whisper.cpp 1.9.0 dropped that line for three cache variables, so the parse returns `None` and the build panics. We accept both forms.

**2. Fail loudly when bindgen fails (not strictly required, but the sharpest edge here).**
Upstream catches a bindgen failure, prints `cargo:warning=Using bundled bindings.rs, which may be out of date`, and copies the checked-in bindings over the freshly built library. In a fork carrying its own whisper.cpp that is *silent* breakage: the shipped 1.8.3 bindings compile against 1.9.4 binaries and disagree about `ggml_type` (40 vs 43 variants) and `ggml_op` (95 vs 101). Only code naming a new symbol fails. We panic instead; `WHISPER_DONT_GENERATE_BINDINGS=1` remains the deliberate opt-out, and `src/bindings.rs` is regenerated so that path is safe too.

## What this buys

whisper.cpp [PR #3677](https://github.com/ggml-org/whisper.cpp/pull/3677) (v1.9.0) adds `whisper_vad_detect_speech_no_reset()` and `whisper_vad_reset_state()`. Silero VAD can then run per frame in a streaming loop without losing its recurrent state. Measured on real meeting audio, per-512-sample frame:

| | Error vs whole-buffer | Cost per frame |
|---|---|---|
| `no_reset` per frame | **0.000 — bit-identical, 1875/1875 frames** | 0.054 ms |
| Sliding 16-frame context (what 1.8.3 forces) | mean 0.060, max 0.87, 85 threshold flips/minute | 0.72 ms |

1.9.4 also fixes beam search carrying state between decodes on a reused `whisper_state`, and is ~2.3× faster on CPU like-for-like. Metal throughput is unchanged; peak RSS is ~28 MB higher.

Still present in 1.9.4, worked around downstream: `no_speech_prob` read from an unwritten logits row, and `GGML_ASSERT` aborting the process on an invalid model `ftype`.

## Bumping whisper.cpp

1. Replace `whisper.cpp/` with the new release tarball, keeping `CMakeLists.txt`, `cmake/`, `include/`, `src/`, `ggml/`, `bindings/`; prune the rest.
2. Build. Diff the regenerated `OUT_DIR` bindings against `src/bindings.rs` to see whether the change is additive.
3. Copy the regenerated bindings over `src/bindings.rs`.
4. Run the consumer's test suite **with models present** and review the golden snapshot: decoder output moves between releases, and that is a product review, not an engineering one.
